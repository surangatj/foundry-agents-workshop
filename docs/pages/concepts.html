Concept guide

The ideas behind the labs, in plain language.

Microsoft Foundry

Microsoft's platform for building, running and governing AI apps and agents: model catalogue, Agent Service, Foundry IQ, Tools, evaluations, observability and the Control Plane, organised in resources and projects.

Foundry Agent Service

The managed runtime for agents. Prompt agents are defined declaratively (model + instructions + tools) and versioned; hosted agents run your own container code. Both are called through the OpenAI-compatible Responses API.

Microsoft Agent Framework

Open-source SDK for Python and .NET that unifies Semantic Kernel and AutoGen: agents, tools, sessions, middleware, multi-agent orchestrations and graph-based workflows. GA since April 2026.

A2A (Agent-to-Agent)

Open protocol for agents to discover each other (Agent Card) and exchange tasks, messages and artifacts across frameworks and vendors. Complements MCP, which connects agents to tools.

Foundry Tools

Built-in and connected tools an agent can call: code interpreter, file search, web search, MCP servers, OpenAPI, Azure Functions, A2A and more. Toolboxes bundle tools behind one MCP endpoint.

Foundry IQ

Knowledge bases built on Azure AI Search agentic retrieval. The agent asks one question; the knowledge base plans sub-queries across sources and returns grounded, cited results.

Orchestration patterns

Sequential, concurrent, handoff, group chat and magentic; or explicit workflows of executors and edges with checkpointing and human-in-the-loop.

Evaluations

Measure quality and safety at scale: agent evaluators (intent resolution, task adherence, tool call accuracy), RAG evaluators (groundedness, relevance), safety evaluators, custom graders and red teaming. Run locally, in the cloud, on a schedule or continuously on live traffic.

Continuous improvement loop

Observe → measure → diagnose → fix → re-measure → ship. Traces and user feedback become test cases; every change ships as a new agent version, evaluated before full rollout.

Fine-tuning

SFT (examples), DPO (preferred vs rejected answers) and RFT (reward from a grader). Global Training and the Developer tier lower the cost of experiments.

Distillation

A large teacher model generates high-quality outputs that become the training data for a smaller, cheaper student model — keeping quality while cutting cost and latency.

Observability

OpenTelemetry tracing of every model call, tool call and handoff into Application Insights, with dashboards for latency, tokens, cost and evaluation scores.

Governance

Entra Agent ID for every agent, RBAC (Foundry User / Project Manager / Account Owner), guardrails (Prompt Shields, content filters, task adherence), the AI Gateway in API Management, and the Foundry Control Plane for fleet-wide inventory, policy and cost.

Region & data residency

This workshop uses Southeast Asia. Global Standard deployments may process prompts in any region while data at rest stays in the resource's geography; check Global Training and Developer-tier fine-tuning against Dialog's data-handling policy before using real customer data.
