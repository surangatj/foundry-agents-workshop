Lab 4 · Agent-to-Agent (A2A)

Dialog Care Copilot — build it step by step.

⏱ 20 minCoreA2A protocolInteroperability
Theory recap · A2A is an open protocol (Linux Foundation) that lets agents built by different teams, in different frameworks, discover each other through an Agent Card (/.well-known/agent-card.json) and exchange tasks over JSON-RPC. MCP connects an agent to tools; A2A connects an agent to other agents.
In this lab you will
  • Host the Roaming agent as an A2A server
  • Discover it from its Agent Card
  • Let the Care Copilot delegate to it as a tool
  • Call a neighbour's agent

Steps

  1. Start the A2A server (terminal 1)

    python -m labs.lab04_a2a_server

    Open a second terminal (+ in the terminal panel) and read the card:

    curl -s http://localhost:9999/.well-known/agent-card.json | python -m json.tool

  2. Call it (terminal 2)

    python -m labs.lab04_a2a_client
    The key lines
    async with A2AAgent(name=card.name, agent_card=card, url=host) as roaming:
    copilot = Agent(client=..., tools=[*ALL_TOOLS,
        roaming.as_tool(name="roaming_specialist", description=card.description)])

  3. Pair up across teams

    In the Codespace Ports tab, right-click port 9999 → Port visibility → Public and share the URL. Your neighbour sets it and calls your agent:

    A2A_AGENT_HOST=https://<codespace>-9999.app.github.dev python -m labs.lab04_a2a_client
    Security: public ports have no authentication — switch back to Private after the lab. Production A2A endpoints sit behind Entra ID / API Management.
🧪 Try it: Hosted agents in Foundry can also be called over A2A, and Foundry agents can call remote A2A agents with the built-in A2A tool — no server code.

Troubleshooting

Connection refused

Is terminal 1 still running? A2A_AGENT_HOST must match the server URL.

Stuck or behind? The complete code for every lab is already in labs/ — run it, read it, move on.
