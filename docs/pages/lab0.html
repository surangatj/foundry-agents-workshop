Lab 0 · Set up your environment

Dialog Care Copilot — build it step by step.

⏱ 10 minCoreSetup
Theory recap · Everything runs in a GitHub Codespace — VS Code in your browser with Python 3.13, the Azure CLI and all packages preinstalled. Use the facilitator's API key or sign in with your Dialog account to access the shared Foundry project.
In this lab you will
  • Open the workshop in a Codespace
  • Configure an API key or Azure sign-in
  • Connect to the Foundry project and get a reply from the model

Steps

  1. Open the Codespace

    Click the button. A browser VS Code opens and installs everything (about 2 minutes the first time).

    Open in GitHub Codespaces ↗

    Prefer your own laptop? Clone the repo, create a Python 3.13 virtual environment and run pip install -r requirements.txt.

  2. Choose authentication

    For API-key access, get the resource key from the facilitators and put it in FOUNDRY_API_KEY in .env. Azure CLI and local administrator rights are not required. Never share or commit the key.

    Alternatively, leave the key empty and sign in in the terminal (Ctrl+`):

    az login --use-device-code

    Open the link, enter the code, sign in with your Dialog account and pick the subscription that holds the Foundry project.

  3. Fill in .env

    The Codespace created .env for you. Open it and set the values below — get them from the facilitators, or find the endpoint and model in the Foundry portal on your project's Overview page and Models page:

    .env
    FOUNDRY_PROJECT_ENDPOINT=https://<resource>.services.ai.azure.com/api/projects/<project>
FOUNDRY_MODEL=gpt-5.4-mini
PARTICIPANT_ALIAS=amila-a
FOUNDRY_API_KEY=<resource key from facilitators; leave empty for Azure sign-in>
    Why an alias? About 60 people share one project. Your alias prefixes every agent you create (amila-a-faq-agent) so nobody overwrites anyone else.

  4. Run the check

    python -m labs.lab00_check_setup

    You should see green ticks and a reply that starts with Ayubowan.

Troubleshooting

az login says my sign-in was blocked

Use FOUNDRY_API_KEY from the facilitators in .env to skip Azure CLI sign-in. Ask Damika / Rusiru for access to a resource that supports API-key authentication.

403 / PermissionDenied when calling the model

You need the Foundry User role on the project. Ask the facilitators to add you.

DeploymentNotFound

FOUNDRY_MODEL must be the deployment name from the Models page, not the model family name.
